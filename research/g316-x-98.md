# Logitech G316 X 98

Findings for the G316 X 98 (ANSI). The labels follow
[README.md](README.md#evidence-labels): live, static, inference.

## Identity (live)

- USB `046d:c36b`. Interfaces 0 and 1 carry key reports, and interface 2
  carries HID++ (vendor usage page `ff00`, report IDs `10` and `11`).
- HID++ 4.2, device name "G316 X 98". Feature `0x4540` reports layout code
  `01`, which Solaar's table maps to ANSI.
- Application firmware `U186.01.B0007`.

## Lighting

- `0x8071` reports two lighting clusters: cluster 0 (location `0x0001`, the
  keys) with six effects and cluster 1 (location `0x0005`, the light bar) with
  five. Both list off, Static `0x01`, `0x0a`, `0x15` and `0x16`; only the keys
  list `0x17`. Solaar names `0x0a` "Breathe" and `0x15` "CycleS". (live for
  the IDs; static for the names) Loginux sends them with Solaar's parameter
  layouts (static), and Breathing and Colour Cycle ran with them on this
  keyboard (live, observed by eye, 2026-10-22).
- `0x8071` getInfo for cluster `0xFF` reads `ff 00 02 00 63 00 26 06`. Byte
  7 counts the effects the keyboard can play on all clusters at once: 6. Read
  one by one (`[ff i 00]`), their IDs are `0x0c`, `0x13`, `0x16` (wave),
  `0x17` (ripple), `0x18` and `0x19`. (live, read only, 2026-10-22)
  - With the wave sent to each cluster, the light bar and the keys around
    Esc, F1 and F2 ran out of step and flickered at the left end, more
    visibly at short periods. Sent once to cluster `0xFF`, the wave ran as
    one across keys and bar with no flicker, also at a 1 to 2 s period.
    Colour Cycle and Breathing, which the keyboard lists only per cluster,
    showed keys and bar in step. (live, observed by eye, 2026-10-22)
- `0x8081` reports 133 zones: `0–66`, `73`, `76–96`, `99–111`, `154`,
  `160–179`, `212–221`. (live)
  - **95 keys**: HID usage minus 3, modifiers 104–111. A channel check on
    2026-10-22 lit each zone alone and found every key where this rule puts
    it. (live)
  - **30-segment light bar** between the function row and the number row:
    zones `160–179`, then `212–221`, from left to right. A red-to-blue
    gradient ran in order and the channel check placed each segment. (live)
  - **No known key**: `0`, `47`, `99–103` and `154` lit nothing visible when
    lit alone. (live) The firmware gives zone 0 no LED channel, and 47 is ISO
    Non-US `#`, absent on ANSI. (static)
- Software control read `00 00` before and after a paint in the morning of
  2026-10-22 and `00 06` that afternoon. After an unplug and replug it read
  `00 00` again, so flags `06` were RAM state that a power cycle clears. What
  set them is unknown. (live)
- Brightness `0x8040` getInfo reads `00 64 05 03`: a maximum of 100, then
  `05` and `03`. (live) Solaar takes the step count, 5, from byte 2 and the
  capability flags from byte 3. (static)

## Other behaviour

- For command shapes, evidence limits and implementation guidance for these
  controls, see [g316-extra-controls.md](g316-extra-controls.md).
- **Report rate.** `0x8061` reports 1000, 2000, 4000 and 8000 Hz (bitmap
  `0078`). Changing the rate re-enumerates the USB device. (live, Windows)
  On Linux the keyboard took a new rate only after `0x8101/6 [05]`, and
  4000 and 8000 Hz did not re-enumerate it. After a replug at 10:02 it came
  back at another rate; through a replug at 11:26 and eight re-enumerations
  of its own it kept 8000 Hz, cause not established. (live, 2026-10-23)
  Nine more followed between 23:06 that day and 03:24 the next, with 8000 Hz
  kept (live, 2026-10-24; see
  [g316-extra-controls.md](g316-extra-controls.md#report-rate-details)).
- **Game mode.** Pressing the game-mode key makes `0x4523` send `01` and `00`
  notifications. (live, Windows)
- **Knob.** The knob is plain HID consumer control: volume up `e9`, volume
  down `ea`, mute on press. (live, Windows) It can also change the lighting
  brightness: the owner turned it on 2026-10-23, and Loginux read the new
  `0x8040` value afterwards (live). How the knob switches to brightness is
  not established.
- **Windows lighting.** Through Logitech's virtual HID device, Windows sees a
  HID LampArray with 125 lamps: 95 keys and 30 accent lamps. The accent lamps
  sit on one straight line at Y ≈ 54.5 mm, X 14.5 to 359.2 mm, which is the
  light bar. The bounding box is 370.6 × 157.0 × 34.43 mm, and the minimum
  update interval is 33,333 µs (30 Hz). Linux has no such device. (live,
  Windows)

## Dot screen

- The small dot-matrix screen draws only built-in states: volume and mute
  from the knob, and lock-key states.
- G HUB 2026.6 offers no screen settings and sent no screen traffic in a
  capture.
- The firmware's display transfer is reachable only through an engineering
  feature that requires vendor authentication. Loginux does not pursue it.

(live for the observations; static for the firmware)

## Sources

The observations above come from:
- live HID++ queries on Linux;
- a USB capture of G HUB 2026.6.981214 on Windows. It is not published,
  because it contains keystrokes;
- static analysis of the firmware image that G HUB caches for this keyboard.
  Neither the image nor the analysis is published.
